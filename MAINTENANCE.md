# Your website: simple maintenance guide

You do not need to become a programmer. Your website is one file:
`index.html`. Keep that file in one local folder and let an AI assistant make
careful edits for you.

## The simple routine

Remember four words: **Ask → Preview → Approve → Publish**

1. **Ask:** Open your website folder in Codex and describe the change in plain
   language.
2. **Preview:** Ask Codex to open the edited `index.html` locally. Check the
   words, links, and appearance.
3. **Approve:** Tell Codex what to correct. Repeat until you are satisfied.
4. **Publish:** Say: “Commit this approved version and push it to GitHub.” The
   public website will normally update within a few minutes.

## Useful requests for an AI assistant

- “Add this new paper to the top of Publications: [paste citation and link].”
- “Move this item from Preprints to Publications and add its journal details.”
- “Update Current Teaching with these courses: [paste courses].”
- “Change only the wording in About. Do not change the design.”
- “Make a backup, then change the green colour to dark blue.”
- “Check every link, preview the site locally, and show me before publishing.”

## One-time local setup

The easiest nontechnical setup is GitHub Desktop:

1. Install **GitHub Desktop** from `desktop.github.com` and sign in.
2. Choose **File → Clone repository**.
3. Select `kwokwingtsoi/kwtsoi.github.io`.
4. Save it somewhere memorable, such as Documents → My Website.
5. Open that local folder in Codex whenever you want AI help.

Do this only once. Afterward, the local folder and GitHub remain connected.

The connected local folder has already been created for you at:
`/Users/kwokwingtsoi/Documents/KW-Tsoi-Website`.

## Adding a PDF paper

1. Put the PDF inside the local `files` folder.
2. Ask Codex: “Add this PDF to Publications and preview the link.”
3. Check the title, co-authors, year, and the PDF itself.
4. Use the normal **Approve → Publish** steps below.

## Publishing with GitHub Desktop

1. Review the local page first.
2. Open GitHub Desktop.
3. Check that only the files you meant to change are listed.
4. In **Summary**, type a short note such as `Add new publication`.
5. Click **Commit to main**.
6. Click **Push origin**.
7. Wait a few minutes and refresh the public website.

## Safety rules

- Never place passwords, private documents, student records, or unpublished
  confidential material in the website folder.
- Always preview before publishing.
- Ask the AI assistant to make a backup before a large redesign.
- Make one subject change at a time: publications, then teaching, then design.
- If something looks wrong, do not panic. GitHub keeps every committed version,
  so an AI assistant can restore the last good one.
